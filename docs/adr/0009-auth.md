# ADR-0009 登入與憑證

## 狀態

已採用。

## 決策

- 登入一律走 WebView（Google ServiceLogin、bilibili passport H5），不自己實作帳密流程。
- 只收 `youtube.com` 的 cookie，並另外存 `visitorData`。Google 在登入過程就會種下 `.youtube.com` 的 cookie，但要等頁面回到 YouTube 才生效。
- visitorData 綁帳號：SAPISID 換了就是換帳號，舊的 visitor id 要清掉。
- 登入憑證（含 visitorData）存 Keychain，不放在 Storage。
- SAPISIDHASH 由 `services/auth.ts` 純 TS 計算；只有 WEB 系 client 能吃（IOS／ANDROID_VR 已移除），VISIONOS 只帶 visitor。
- 登入後的請求要指定第一個帳號槽。
- 沒登入也留一筆空殼 profile：紀錄便宜但形狀一致。
- Keychain 被拒（鎖定或容量）時，登入退回合約資料的沙盒副本繼續可用（見 issue-006）。
- WebView 注入失敗不擋登入。

## 後果

憑證與 cookie 只在 WebView 與 Keychain 之間流動，其他層只看 provider 的登入狀態。
